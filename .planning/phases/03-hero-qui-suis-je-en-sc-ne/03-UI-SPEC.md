# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** (1) the hero: screen frame, pre-rendered grain, title-card positioning and availability lines, Open Graph; (2) « Qui suis-je »: two-column layout, CSS viewfinder portrait, CV video card, four text slots; (3) the skills grid (3 trade groups, 13 tools, monogram fallback); (4) motion: `Reveal` shutter and the global reduced-motion guard; (5) `src/content/copy.ts` as the single home of every user-facing string. Everything else is phase 4 (project cards and pages) or phase 5 (contact, QA).
>
> Sources: 03-CONTEXT.md (16 locked decisions), ROADMAP Phase 3 (5 success criteria), REQUIREMENTS (HERO-02..04, ABOUT-01..04, TEXT-01..02, PERF-01), 02-UI-SPEC.md (scale, roles, toggle), FEATURES.md (§ Text slots, § Logos, anti-features), PITFALLS.md (12: grain, overlays, reduced motion; SSR hydration), `src/styles.css`, `src/routes/index.tsx`, `src/routes/__root.tsx`, `src/components/Picture.tsx`, `src/components/Reveal.tsx`, `src/data/media.generated.ts`, orchestrator pre-answers. Anything not in those sources is labelled **(Claude's discretion)**.

## Typography

Four roles and two weights. **In this phase the legacy off-scale sizes of the hero and About are collapsed onto the scale:** hero h1 `text-6xl sm:text-8xl md:text-9xl` (60/96/128) → Display; hero subtitle (italic 20/24) → removed and replaced by the title-card lines; About h2 `text-4xl sm:text-5xl` (36/48) → Display 48; `hud-tag` skill chips → removed (replaced by the grid).

| Role | Size | Weight | Line height | Font and case | Used by |
|------|------|--------|-------------|---------------|---------|
| Body | 16px (`text-base`) | 400 | 1.625 (`leading-relaxed`) | DM Sans | `about.intro`, `dd` texts (specialty, range), CV error message |
| Label | 12px (`text-xs`) | 500 for title-card lines, group headings and `dt`; 400 for tile captions | 1.333 (16px) | DM Sans, **uppercase, `letter-spacing: 0.12em`** for title-card lines, group headings, `dt`, the CV label and « REC ». Tile captions are sentence case with no tracking. | `hero.tagline`, `hero.availability`, « Vidéo · Design · Web », « Spécialité » / « Polyvalence MMI », « CV vidéo — 1:25 », « REC », tool names |
| Heading | 24px (`text-2xl`) | 400 | 1.333 | Cormorant Garamond | `about.goal` (lead sentence), `skills.title` h3 |
| Display | 48px below 640px, 72px from 640px (`text-5xl sm:text-7xl`) | 400 | 1.0 (`leading-none`) | Cormorant Garamond | Hero `h1` (48 → 72). About `h2` stays at **48px at every breakpoint**. |

- **Title-card decision (fixed):** uppercase, not small caps. DM Sans has no true small-caps glyphs and `font-variant: small-caps` would be synthesised. The values are 12px, weight 500, `letter-spacing: 0.12em`, `line-height: 16px`.
- Monogram initials: Cormorant Garamond 16px weight 500. This reuses the Body size and the 500 weight, so no new size is added.
- Weights in this phase's new UI: **400 and 500 only.** Weight 700 is not loaded for DM Sans and must not be used in new UI (the legacy `sae-2` bold stays untouched under PROJ-07).
- `<em>` in the h1 (« Rebahi ») and the h2 (« suis-je ? ») keeps `text-[var(--sakura)]`, as it does today.
- `hud-tag` (0.72rem) stays as is for the project cards (phase 4) and is no longer used in About.

## Color

Always reference the variable, never a hex. Hex values are sRGB approximations for review only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The hero video under its plum gradient (home backdrop), plus `--card` oklch(0.99 0.005 70) ≈ #FDFBF8 and `--cream` oklch(0.975 0.012 70) ≈ #FBF6EF | Video: full hero and the backdrop behind About. Card: the About text card, the skills card, and the tile background (`--cream`). |
| Secondary (30%) | `--plum-ink` rgb(61 31 58) at 0.55–0.92 alpha (hero gradient, frame matte, title-card bands, CV overlay, REC band) and at full opacity for About text | Scrims and matte; About text colour on cards |
| Accent (10%) | `--gold` oklch(0.78 0.1 80) ≈ #E3B870 | Reserved list below |
| Highlight (existing) | `--sakura` oklch(0.82 0.09 8) ≈ #F2B3BA | Focus rings, `<em>` in titles, REC dot, CV play glyph and disc border, monogram disc |
| Hairline (existing) | `--border` oklch(0.9 0.03 10) | 1px border of skill tiles |
| Frame edge (locked) | `--plum` (the existing token) | 1px border of the hero screen frame (CONTEXT decision) |
| Destructive | `--destructive` | Not used. This phase has no destructive action. |

**Why `--plum-ink`:** the current `--plum` token resolves to a translucent grey-green (`oklch(48% 0.048 155 / 0.618)`). Over `--card` it measures about 2.6:1, which fails WCAG 1.4.3 for body text. The redesigned About text (lead, intro, `dt`/`dd`, group headings, captions) uses `var(--plum-ink)` at 100%, about 13:1 on `--card`. Legacy sections (Projects, project pages) are not recoloured in this phase.

Accent (`--gold`) is reserved for:
1. The 4 viewfinder corner brackets on the portrait (new)
2. `quest-btn` border and corner brackets, including the hero CTA (existing)
3. `ornament-card` 1px border at 35% on the About and skills cards (existing)
4. The hero pause toggle's 1px border (phase 2, unchanged)
5. The `·` separators between the group names in `skills.groups` if they are rendered inline (existing ornament pattern)

Gold is **not** used for text, focus rings, the screen-frame edge, the tile borders, or the CV play control.

Contrast contract (WCAG 2.2 AA):
- Title-card lines: `var(--cream)` text on an inline band `rgba(61,31,58,0.85)`. This is the scrim validated in phase 2. Over a pure-white video frame it resolves to about #5A4057, giving about 8:1 (target 4.5:1). The band is required and must not be replaced by a `text-shadow`.
- CV label pill and « REC » label: same band, same result.
- CV play disc: sakura glyph (≈ #F2B3BA) on `rgba(61,31,58,0.85)` measures about 6:1, above the 3:1 non-text minimum.
- Skill captions and group headings: `--plum-ink` on `--card`/`--cream` is about 13:1.
- Monogram initials: `--plum-ink` on `--sakura` is about 8:1.
- Focus: 2px `var(--sakura)` outline, 2px offset, on every new interactive element.

**Screen frame (`.cinema-screen`), decorative, `aria-hidden="true"`, `pointer-events: none`:**

| Property | Contract |
|----------|----------|
| Placement | `absolute` inside the hero section (it scrolls away with the hero; **not** `fixed`), `z-0`, below the content (`z-10`). Pause toggle (`fixed z-30`) and nav (`fixed z-40`) always sit above it. |
| Inset | **0 below 640px (full-bleed, no gutter loss on mobile)**, 16px at 640–1023px, 24px from 1024px |

**Grain (`.cinema-grain`), a child of the frame, `aria-hidden="true"`, `pointer-events: none`:**

| Property | Contract |
|----------|----------|
| Source | Pipeline-generated 256×256 WebP, **< 10 KB**, manifest entry `grain`. The URL is passed from `Hero` (which may read `media.generated`) to `ScreenFrame` as the CSS custom property `--cinema-grain-url: url(…)`. `ScreenFrame` never imports data. Pipeline guidance: luma-only noise, low amplitude around mid-grey, lossy q≈40. If the file exceeds 10 KB, lower the amplitude, not the tile size. |
| Layer | `absolute; inset: 0; background-image: var(--cinema-grain-url); background-repeat: repeat; background-size: 256px 256px; opacity: 0.07; will-change: transform` (the only new promoted layer; total promoted layers on the page ≤ 2) |
| Animation | `@keyframes cinema-grain` steps `background-position` through 8 offsets (multiples of 32px, both axes), `animation: cinema-grain 1s steps(8) infinite` |
| Coupling to the pause toggle | The grain animates **only while the hero video is playing**: `Hero` sets `data-playing="true|false"` on the frame from its existing state, and `[data-playing="false"] .cinema-grain { animation-play-state: paused; }`. The phase-2 toggle therefore also stops the grain (WCAG 2.2.2). SSR renders `false`. |
| Reduced motion | `display: none` (the layer is removed, not frozen) |
| Replaced | The legacy `.grain::before` rule (live SVG `feTurbulence`, opacity 0.18, `mix-blend-mode: overlay`) is **deleted** from `styles.css` |

### 5. `Reveal` shutter and global motion guard

**`Reveal` (existing component, same API):** keeps `opacity 0 → 1` over 0.9s and `translateY(24px) → none`, and gains a vertical shutter:

```css
.reveal    { clip-path: inset(-64px -64px 100% -64px); transition: opacity .9s ease, transform .9s ease, clip-path .32s cubic-bezier(.2,.7,.2,1); }
.reveal.in { clip-path: inset(-64px); }
```

The negative insets keep shadows (`--shadow-quest`, `quest-card` hover shadow ≤ 52px) and `quest-btn` brackets unclipped once revealed. The `IntersectionObserver` threshold stays at 0.12 and fires once.

**`useReducedMotion()` (`src/hooks/use-reduced-motion.ts`):** `useSyncExternalStore(subscribe to matchMedia change, () => matchMedia(...).matches, () => false)`. It is only read inside effects or event handlers. **No render output branches on it**, so there is no hydration mismatch. Consumers: `Hero` (autoplay decision, visibility resume).

**Global CSS guard (`@layer cinema`, shipped in the same commit as the first new animation):**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important; transition-duration: .01ms !important; }
  html { scroll-behavior: auto; }
  .reveal, .reveal.in { opacity: 1; transform: none; clip-path: none; }
  .cinema-grain, .cinema-rec, .cinema-viewfinder::after { display: none; }
  .quest-card:hover, .quest-btn:hover, .cinema-tile:hover { transform: none; }
}
```

Acceptance: with the OS setting on, grain, REC, sweep and reveals are static, the brackets remain, and the hero shows its poster with the toggle in the paused state (phase-2 behaviour). A production build's console shows no hydration warning.
